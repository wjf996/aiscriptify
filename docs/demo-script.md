# Demo 讲解脚本

建议视频时长控制在 3 到 5 分钟。

## 1. 开场

大家好，我是七牛云 XEngineer 暑期实训营第三批次参赛者。我的作品是 aiscriptify，一款 AI 小说转剧本工具。

这个项目解决的问题是：很多小说作者想把自己的小说改编成剧本，但从小说叙事转成剧本结构需要整理章节、角色、场景、动作和对白，门槛比较高。aiscriptify 可以把 3 个章节以上的小说文本转换成可编辑的 YAML 剧本初稿。

## 2. 功能演示

首先进入页面，可以看到小说输入区。这里支持直接粘贴小说文本，也支持导入 `.txt` 或 `.md` 文件。

输入区会实时统计章节数和字数。如果不足 3 章，页面会提示还不能生成；满足 3 章后，会显示可生成。

我点击填充示例，然后选择剧本类型。这里有三种类型：

- 影视剧：偏画面、动作和镜头。
- 短剧：偏冲突、反转和节奏。
- 广播剧：偏旁白、音效和对白。

点击生成后，页面会显示生成进度，包括校验章节、调用 AI、整理 YAML 和生成摘要。

生成完成后，小说输入区会自动收起，让用户聚焦右侧剧本结果。

## 3. 剧本结果说明

生成结果会展示章节数、角色数和场景数，还会列出识别出的角色和场景摘要。

在章节导航中，可以切换查看每一章的摘要、本章角色和本章场景。

YAML 预览区支持行号和语法高亮。长文本会自动换行，不需要左右拖动。用户也可以切换到 YAML 编辑 Tab，直接修改生成的剧本初稿。

## 4. 打磨能力演示

点击打磨建议，系统会基于当前 YAML 给出作者可以继续修改的方向，例如角色动机、场景冲突、对白语气和节奏结构。

点击某条建议后，页面会自动切换到 YAML 预览，并高亮建议检查的字段位置，帮助作者知道应该改哪里。

## 5. YAML Schema 说明

本项目要求输出格式必须是 YAML，所以我额外编写了 YAML Schema 文档。

Schema 的核心字段包括：

- `title`
- `script_type`
- `characters`
- `chapters`
- `scenes`
- `dialogues`

我保留英文 key，是因为英文 key 更适合程序解析和后续扩展；但所有作者阅读的内容都使用中文，并且文档中有中文解释。

为了让剧本更专业，我还设计了可选扩展字段，例如：

- `emotion`：角色说话时的神情或情绪。
- `shots`：影视剧分镜建议。
- `hook`：短剧反转或悬念。
- `sound_effects`：广播剧音效。
- `narration`：广播剧旁白。

这些字段不是强制必填，而是作为进一步打磨剧本的扩展能力。

## 6. 技术架构

项目采用前后端分离：

- 前端使用 React、Vite、TypeScript 和 Mantine。
- 后端使用 FastAPI、Pydantic 和 PyYAML。
- AI 生成使用 DeepSeek API。

后端负责章节校验、AI 调用、YAML 校验和打磨建议接口。前端负责输入、生成状态、YAML 编辑预览、打磨建议和导出。

## 7. 开发过程

项目采用 GitHub PR 分阶段开发，每个 PR 只做一件事。从初始化项目、前端布局、后端接口、AI 接入，到 YAML 预览、打磨建议、文件导入和剧本类型差异化生成，都是逐步合并完成的。

这样可以保证开发过程清晰，每次合并后主分支都能运行。

## 8. AI 辅助说明

本项目使用 AI 工具辅助需求拆解、代码实现建议、问题排查和文档优化。但项目的功能设计、技术取舍、代码整合、测试验证和最终提交由我本人完成。

项目中的 AI 生成结果定位为可编辑初稿，作者仍然可以继续修改、校验和导出。

## 9. 收尾

aiscriptify 的核心价值是降低小说作者改编剧本的第一步门槛，让作者快速获得结构清晰、可继续打磨的 YAML 剧本初稿。

我的演示到这里结束，谢谢大家。
